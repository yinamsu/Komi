KOMICARE System Whitepaper

"Empowering medical travelers with unedited verified data, personalized Fitzpatrick matching, and privacy protection."

KOMICARE is a next-generation K-Beauty skin matching and safety verification landing platform. The platform address a critical pain point in the foreign medical tourism market: the prevalence of sponsored fake reviews, factory-style clinics performing hurried procedures, and the fear of legal retribution due to restrictive local defamation laws.

By introducing decentralized/offshore hosting strategies, client-side data privacy masking, clinical qualification filtering, and customized skin passports based on Fitzpatrick skin type diagnostics, KOMICARE matches international patients with premium boutique clinics prioritizing safety and board-certified expertise.

Core Value Proposition

KOMICARE acts as an independent trust layer between global medical consumers and Korean aesthetic clinics. We calibrate skin safety parameters before booking and guarantee raw, unedited patient reviews hosting data outside censorship-prone local jurisdictions.

3. Core Features Specifications

Fitzpatrick Diagnostic Skin Passport

Calculates a patient's Fitzpatrick Skin Type (Type I to Type VI) via an interactive questionnaire checking:

  • Skin color reactions to sun exposure (burning vs tanning).
  • Genetic skin tone characteristics.

Produces a downloadable Skin Passport card detailing specific laser energy calibration instructions. This card is given to doctors to prevent over-treatment burns common on reactive skin barriers.

Receipt Privacy Tax Masker

To protect patients who leave negative reviews from being tracked down by clinics using purchase timestamps, KOMICARE features an interactive client-side blur engine. When a patient uploads their tax refund receipt, it automatically hides:

  • Unique transaction refund serial numbers.
  • Exact minute/second timestamps.
  • Staff codes and cash register IDs.

Real-time Multilingual Filters

Offers precise hospital mapping using a 14-toggle filter panel translating dynamically between English, Korean, and Japanese. The filters query:

  • Doctor qualifications (Dermatologist, Specialist, General Practitioner).
  • Clinical experience (0-5, 5-10, 10+ Years).
  • 12 Detailed Review Category Star ratings (Satisfaction, Cost value, Response speed, Wait time, Language access, Friendliness, Honest treatment, Location, Facility comfort, Aftercare, and Parking).

500-Clinics Programmatic Scaler

To ensure robust filter coverage and stress-test listing rendering without database bloat, KOMICARE uses a pseudo-random generator (PRNG) that expands base listings to 500 unique clinics on the fly. Experience years, scores, and safety certificates are deterministic and stable per clinic ID.

4. System Architecture

KOMICARE is built as a highly performant, serverless Jamstack application. 

[Client Browser] 
    │
    ├── (Reads Static HTML/CSS/JS) ──> Vercel Edge CDN
    │
    ├── (GET /api/clinics) ──────────> Vercel Serverless Function ──> Supabase DB
    │
    └── (POST /api/submit-clinic) ───> Vercel Serverless Function ──> Supabase DB

Frontend Implementation

  • Layout & Logic: Vanilla HTML5 and ES6 Javascript. Avoids bulky JS frameworks to maintain sub-second First Contentful Paint (FCP) on international mobile connections.
  • Design Tokens: Managed in [index.css](file:///e:/Komi/index.css) using HSL custom variables. Premium dark mode aesthetic with micro-animations.
  • Internationalization: Translation dictionary engine in [i18n.js](file:///e:/Komi/i18n.js) which scans `data-i18n` and `data-i18n-html` elements for instant, layout-shift-free translations.

Backend Service Layer

  • Serverless Hosting: Vercel Functions. Executes endpoints inside isolated runtime environments that automatically scale down to zero when inactive.
  • API Handlers: Written in Node.js, utilizing CORS preflight protection headers to block unauthorized third-party scrapers.

5. Database Table Layouts

KOMICARE hosts data in a secure PostgreSQL database on Supabase. Row-Level Security (RLS) is enabled to protect patient data.

Table: public.clinics

Column Name Data Type Description
id SERIAL (Primary Key) Unique auto-incrementing ID.
name TEXT Clinic name (Bilingual string e.g. A | B).
location TEXT District and area coordinates.
rating TEXT Stars rating label string.
specialties TEXT[] Array of certified treatment tags.
doctor_type TEXT dermatologist, specialist, or gp.
experience_years INTEGER Total years of clinical experience. Default 7.
sleep_anesthesia BOOLEAN True if sleep anesthesia is available.
anesthesiologist_resident BOOLEAN True if anesthesiologist is present on-site.
foreign_attraction_registered BOOLEAN Government attraction certification flag.
active BOOLEAN Soft-delete listing control flag.

Table: public.leads

Column Name Data Type Description
id UUID (Primary Key) Randomly generated UUID.
email TEXT (Unique) User email address (protected from public read by RLS).
fitzpatrick_type SMALLINT Skin diagnostic score (1 to 6).
created_at TIMESTAMPTZ Auto-inserted registration timestamp.

6. Scaling Roadmap & Milestones

As the platform transitions from launching landing page metrics to real medical listings, we have planned the following milestones:

Phase 1: Real-time Booking Verification Integrating clinic calendars with the bookings table, enabling deposits to secure surgical schedules.

Phase 3: Doctor Credentials Verification Adding API verification checks with local medical associations to automatically flag clinics misrepresenting GP staff as Board-Certified Dermatologists.
